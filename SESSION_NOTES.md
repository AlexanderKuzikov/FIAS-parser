# FIAS-parser — Заметки сессии (2026-03-26)

## Цель
Обогатить базу судов (`courts.json`, 10206 записей) данными из ГАР (ФИАС):
- `objectguid` — GUID дома из ГАР
- `oktmo` — код ОКТМО муниципального образования

Пилот: регион **59 (Пермский край)**, 182 суда → **182/182 найдено (100%)**.

---

## Архитектура данных

### Входные файлы
- `data/courts.json` — база судов: `code`, `name`, `inn`, `court_type`, `address`, `legal_address`, `website`
- `data/59/AS_ADDR_OBJ_*.XML` — адресные объекты (улицы, города) региона
- `data/59/AS_MUN_HIERARCHY_*.XML` — муниципальная иерархия + ОКТМО
- `data/59/AS_HOUSES_*.XML` — дома

### Промежуточные файлы (`data/`)
| Файл | Содержимое |
|------|-----------|
| `addr-map-59.json` | `"тип:Название" → [{OBJECTID, OBJECTGUID, LEVEL}]` — все адресные объекты |
| `mun-map-59.json` | `OBJECTID → {PATH, OKTMO, ...}` — иерархия и ОКТМО каждого объекта |
| `houses-map-59.json` | `houseObjectId → {OBJECTGUID, HOUSENUM}` — все дома |
| `street-houses-map-59.json` | `streetObjectId → [{houseObjectId, OBJECTGUID, HOUSENUM}]` |

### Выходной файл
- `data/resolved-59.json` — суды с `objectguid` и `oktmo`
- `data/courts-59.xlsx` — то же в Excel

## Ключевые решения

### 1. Строения (HOUSETYPE=7)
Строения в ГАР хранятся как отдельные дома с `HOUSETYPE=7`.
В `AS_MUN_HIERARCHY` путь строения: `регион.город.улица.дом.строение`.
**Проблема:** при построении `street-houses-map` предпоследний элемент PATH
для строения указывал на основной дом, а не на улицу.
**Решение:** в `build-street-houses-map.mjs` — если родитель сам есть в `housesMap`,
подниматься на уровень выше по PATH.

```js
if (housesMap[streetObjectId] && pathParts.length >= 3) {
    streetObjectId = pathParts[pathParts.length - 3];
}
```

### 2. Парсер адресов (`parseAddress`)
Адреса в `courts.json` непоследовательны. Итоговый парсер:
- Разбивает по запятым
- Ищет дом с конца: `д`, `зд`, `здание`, `стр` + голый номер
- Отбрасывает корпус (`к 2`)
- Двойные адреса (`ул X, 31/Лодыгина, 41`) — берёт до `/`
- Улицу ищет ближайшую перед домом по словарю типов
- Населённый пункт — ближайший перед улицей

**Словарь нормализации типов улиц:**
```js
'пр-кт' → 'пр-кт', 'пр' → 'пр-кт', 'просп' → 'пр-кт'
```
(в addr-map ключи хранятся как `пр-кт`, не `пр`)

**Фоллбэк номера дома:** `1А` → если не найден, пробуем `1` (без буквы).

### 3. Фильтрация по городу
Одна улица (напр. `ул:Пушкина`) есть во многих городах региона.
Без фильтрации брался первый попавшийся — мог оказаться другой город.
**Решение:** фильтруем кандидатов-улиц через PATH в mun-map:
берём только те, чей PATH содержит OBJECTID нужного населённого пункта.
**Фоллбэк:** если после фильтрации ничего не найдено — ищем без фильтра.

```js
const f = allCandidates.filter(street => {
    const path = munMap[street.OBJECTID]?.PATH ?? '';
    return [...localityIds].some(id => path.includes(id));
});
if (f.length > 0) filteredCandidates = f;
```

### 4. ОКТМО
Поле `OKTMO` хранится прямо в `AS_MUN_HIERARCHY` — в записи каждого объекта.
Уже сохранено в `mun-map-59.json`. Для получения ОКТМО дома:
```js
const houseObjectId = guidToHouseId[objectguid];
return munMap[houseObjectId]?.OKTMO ?? null;
```
Все суды Перми имеют ОКТМО `57701000001` — это нормально,
один код на всё городское муниципальное образование.

## Проблемы и решения

| Проблема | Решение |
|---------|---------|
| `стр 50` без `д` — parse_error | Regex захватывает `д\|зд\|стр` |
| `зд 3` (здание) — parse_error | Добавлен `зд` в regex |
| `ул 1905 года` — regex требовал заглавную | Убрано требование заглавной буквы |
| `ул богдана:Хмельницкого` — неверный разбор | Regex ищет тип строго по словарю |
| `пр-кт` → не найден (был маппинг в `пр`) | `пр-кт` оставлен как есть в словаре |
| `д 96/1` — дробный номер | `.split('/')[0]` |
| `д 192 к 2` — корпус в том же сегменте | Regex `(?:\s+к\.?\s*\S+)?` в конце |
| Строения не привязаны к улице | PATH строения на 3 уровня, не 2 |
| Неверный город при совпадении улиц | Фильтрация через PATH + фоллбэк |
